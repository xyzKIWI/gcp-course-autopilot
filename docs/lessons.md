# 踩坑紀錄

1. **`--sandbox` 不一定是隔離。** 在「自動同意所有工具」的設定下，某代理人 CLI 會自行繞過 sandbox 讀檔、執行指令、上網。要真正「無工具」，請用純模型的 HTTP API。
2. **測隔離不要在 prompt 裡叫它別用工具。** 模型照做會讓你誤以為被擋住。用 canary 檔案，並明確要求它「用任何工具去讀／執行／上網」，看實際結果。
3. **排程環境 ≠ SSH 環境。** 同一個 CLI 從 SSH 呼叫會說「未登入」，由 launchd 在使用者的圖形登入階段呼叫卻正常（鑰匙圈只在後者可用）。要在「真的會跑的環境」測。
4. **送出成功不能只看 HTTP 200。** 平台可能回 200 但內容是錯誤頁；要找平台自己的成功訊息，並以學員卡回讀為準。
5. **送出之後的任何錯誤都算「結果不明」。** 包括轉址失敗、跟隨轉址時斷線。這時重送可能造成重複。
6. **「待確認」要先寫進磁碟再送出。** 否則送出後剛好當機，下一輪就不知道自己送過。
7. **流程結束後，平台可能移除狀態頁上的項目。** 程式要在時間窗內完成驗收，窗後只做最後確認與通知，並停止輪詢。
8. **讀別的程式的狀態檔，要照實際格式，不要照想像的規格。** 尚未報名的項目根本沒有 `status` 欄位；照「缺欄位就告警」實作會天天假警報。
9. **新版 API 金鑰格式可能跟舊版不同。** 用「看起來像金鑰的字串」去遮罩會漏；要按欄位位置遮罩。
10. **自動化瀏覽器可能被服務方判定為可疑。** 某些主控台（例如建立 API 金鑰）會拒絕自動化瀏覽器的請求，要由人手動完成。
11. **演練模式不能改動任何本機檔案。** 連「把壞掉的狀態檔改名備份」都不能做；也要寫清楚它仍會登入一次，不要宣稱「完全唯讀」。
12. **專案放哪台機器的哪個目錄要先看規矩。** 兩台機器的目錄慣例不同，照抄另一台的路徑會污染工作目錄。
